# KV-INT8-G64 implementation plan (Qwen4-Exp QSA layers)

Winner: INT8-G64 (index-codesign) with grafts: scales inside the lazy VMM arena (minimal-kernel), row-gather kernel with runtime length for prefix prefill (avoids the constexpr-`topk` recompile trap), env-gated fake-quant step 0 (SP-INT8), optional static per-channel smoothing applied inside the kernels (kv-asymmetric, but no output-side fold, no fp8-dtype piggyback). Selection-tiers dropped (accuracy-first target).

Measured basis (perf/nll/kv_stats_fp8run.pt; top-level dict keyed by local QSA layer 0..11, ~19k tokens each, fields `n`, `k_sumsq_ch`/`v_sumsq_ch` [2,256], `*_tok_ratio_hist`): post-norm K channel-RMS max/median 2.9-6.6 (layer 6 head 0: 6.6), V 2.8-6.4; K token spikes absent, V tokens with absmax/mean|x| >= 24: 0.00-0.13 % (worst layer 8). Simulation on these channel profiles (Student-t(6) tokens, 4096 rows), relative RMS error: e4m3 2.66 % | int8 per-token 1.31 % (K) / 1.33 % (V) | int8 g64 0.89 / 0.94 % | g32 0.74 / 0.77 % | g64 + static per-channel smoothing 0.76 / 0.76 %. Error-variance ratio vs e4m3: per-token 0.24x, g64 0.11-0.12x, g32 0.08x, g64+smooth 0.08x.

## 1. Storage layout, bytes/token

Per QSA layer l (12 layers, local index 0..11), rows = size + page_size (131,136 at 131,072 tokens), NHD as today (`_kv_buffer_shapes` memory_pool.py:2167-2178):

| buffer | dtype/shape | B/token/layer |
|---|---|---|
| k_buffer[l] | int8 [rows, 2, 256] | 512 |
| v_buffer[l] | int8 [rows, 2, 256] | 512 |
| k_scale_buffer[l] | fp16 [rows, 2, 4] (absmax/127 per (token, kv-head, 64-channel group); group 0 = rotary dims 0..63, groups 1-3 = pass-through) | 16 |
| v_scale_buffer[l] | fp16 [rows, 2, 4] | 16 |

Total 12 x 1056 = **12,672 B/token = 12.4 KB** (bf16 24,576; fp8 12,288). Compressed index-K cache stays bf16 (768 B/token, qsa_kv_pool.py:36-53) -> full QSA state 13,440 B/token. Stage B adds two constants sm_k, sm_v fp16 [12, 2, 256] (12 KB total, identity by default). `self.dtype = self.store_dtype = torch.int8` (KVCache.__init__ only maps fp8 to uint8, memory_pool.py:1757-1761), so `get_key_buffer` (:2500-2506) returns the raw int8 tensor and every itemsize-driven path (descs :2239, pool_configurator cell size :249) sees 1 B. Quantization: s = absmax_group/127 (s = 1.0 when absmax == 0), q = rint(x/s) clamped to [-127,127]; dequant q*s in fp32 -> bf16. GROUP is a `tl.constexpr`: 256 (12,384 B/token) and 32 (12,960 B/token) are one-constant variants.

```

```

## 4. Prefix-chunk prefill

Backend :1466-1504: replace :1473-1490 (uint8 view, per-request index_select, cat, fp8 `.to`) with, when `k_buffer.dtype == torch.int8`:
- move `sequence_lens_tensor`/`cu_seqlens_k` (:1491-1495) above the gather; `max_len = max(sequence_lens)`; `req_idx_t = forward_batch.req_pool_indices` (device tensor, do not `.tolist()`).
- `packed_k, packed_v = torch.empty((int(cu_seqlens_k[-1]), 2, 256), bf16)` x 2, allocated PER CALL (the prefix path is never graph-captured) -- NOT `_fa2_scratch` (:1521-1538): `_get_fa2_scratch` is keyed by (heads, dim, dtype, device) and reallocates when capacity grows; the decode CUDA graph captured the pointer of that buffer, so a prefill-sized request would silently break the captured graph -- and not a retained backend buffer either: the packed bf16 K/V is 2 x 1 KB/token = 256 MB for a 128k prefix (512 MB at 256k), and a retained copy would permanently reduce the driver-free memory that `lazy_ensure`'s headroom check and the elastic expert cache size against. Per-call `torch.empty` gives the same caching-allocator reuse as today's per-layer cat temporaries (same 2 KB/token footprint, same lifetime).
- `_gather_dequant_rows_int8[(batch, cdiv(max_len, 16), 2)]`: program (b, blk, h): `len = load(seq_lens + b)`, `req = load(req_indices + b)`, `t = blk*16 + arange(16)`, `valid = t < len`, `slot = load(req_to_token + req*req_stride + t, mask=valid)`, `dst = load(cu_k + b) + t`; body identical to the `_compact_kv_int8` dequant (scale index `(slot*2+h)*4 + dims//64`, sm multiply), store bf16 rows to packed_k/v. `max_len` is a grid dimension, not a constexpr -> no recompile per chunk (the reason not to reuse `_compact_kv` with `topk = max_len`, whose `topk` is constexpr at :380/:420).
- then `sparse_gqa_fwd_interface_triton_ck(q, packed_k, packed_v, ...)` (:1496-1504) unchanged; its `.contiguous()` (:267) is a no-op; the chunk kernel (:168-263, `tl.dot(q_values, keys)` :246) is untouched. The no-prefix first chunk (:1454-1464) still attends the projected bf16 k/v (exact). Traffic: 528 B read + 1 KB write per prefix token per layer vs 2 x (1 KB + 1 KB) today.
- Stage B follow-up (not day 1): int8 + scale loads inside `_sparse_gqa_chunk_prefill` via a slot table, dropping the whole-prefix materialisation (the 256k blocker, CAMPAIGN.md:339).

## 8. Risks and pre-checks

- V single-channel token spikes (0.02-0.13 % of rows, layer 8 worst): with g64 the spike coarsens one 64-group only; pre-check = A0 `int8_g32` vs `int8_g64` on nll_long; mitigation GROUP=32 for V (+96 B/token).
- Static channel spread 3-6.6x in K and V is only partly fixed by g64 (0.11x variance); pre-check = A0 `int8_g64_sm`; mitigation = stage B smoothing (0.08x).
- Every fp8 dispatch site must accept int8 or it silently feeds int8 bytes to a bf16 kernel: backend :1473, :1598, :1727, sparse_attn.py:472; radix_attention.py:211 is unaffected (v stays bf16). Pre-check: grep `float8_e4m3fn` in the QSA files (4 hits listed) and assert `out_k.dtype == bf16` in the int8 branch.
- Scratch reallocation under CUDA graph (section 4): prefix gather must never use `_get_fa2_scratch`; pre-check = run a 20k prompt after graph capture, then decode.
- VMM owner constraints: scale descs must be int8 [rows,16] (single store_dtype, span check :303-307); forgetting `.view(fp16)` or zeroing beyond the backed floor faults; pre-check = startup log shows 12.4 KB/token and `lazy_release` after the first request.
- Zero-magnitude rows: s = 1.0 when absmax == 0, fp16 scale subnormal below 6e-5 (harmless); NaN guard = clamp in kernel, masked loads `other=0`.
- Consumers that read the pool without scales (CPU fallback :1431-1442/:1676-1680, get_cpu_copy/load_cpu_copy :2441/:2463, set_kv_buffer_prefix_valid :2920, `_move_kv_cache_impl` :3037 with spec, PD buf infos): all raise for the int8 pool; none are used in the accepted state (no spec, no radix, no hicache).
- HybridLinearKVPool passes `k_scale=1.0` floats (:4053-4076): ignore scalar 1, reject anything else.
- Capture safety: the write kernel's grid (N,2) and `loc` are static in the breakable decode graph; the scale/sm tensors must exist before capture (they do: allocated in `_create_buffers`).
- Speed attribution: if decode reads -3 % again, time `_compact_kv_fp8` vs `_compact_kv_int8` in isolation before rejecting (same traffic + one FMA per element); one extra in-graph launch per QSA layer (~3 us x 12).
- Accuracy harness blindness (nll_eval/logprob_diff short prompts) is the single biggest way to accept a broken cache: gates 2-3 above are mandatory, gate 1 is not evidence.
